## Intent

**Problem:** The Sandbox only slides a square; there is no per-Player structure, aim, DASH, buffering, Perfect Dodge, time-scale ownership or pause menu, so combat feel cannot be judged (stories 2.1–2.5).

**Approach:** Pure rules in `GMR.Core` (MoveMath, AimResolver, InputBuffer, DashState, InvulnerabilityTracker, TimeScaleService, PendingHitRegistry, registries, events, EncounterContext) with EditMode tests; thin MonoBehaviour adapters in `GMR.Runtime` (EncounterBootstrap, PlayerRoot, HeroRuntime, HeroMover, DashController, visuals, PauseController); DummyAttacker + debug toggle panel in `GMR.DevTools`; scene/prefabs/assets generated by a `GMR.Editor` builder run in batchmode.

## Boundaries & Constraints

**Always:** per-Player instances only (PlayerId from PlayerInputManager manual join); every number in a `*Config`/`*Definition` SO read live each use; SOs never written at runtime (menu toggles go to a per-encounter `SessionToggles` override object); only the TimeScale driver writes `Time.timeScale`; only `PlayerInputReader` touches `InputAction`; `DashController` sole raiser of `DashStarted`/`PerfectDodged`; scaled time for gameplay, unscaled for UI/time-scale expiry; Input System stays 1.19.0; BannedApiTests green.

**Never:** static player/mutable statics/static events; runtime `FindObjectOfType`; Runtime referencing DevTools; `UnityEngine.Random`/`System.Random`/`DateTime.Now`; damage/HP (Epic 3); right-stick aim (enum hook only); commits.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected |
|---|---|---|
| Dead-zone | stick 0.15 (dz 0.2) | zero velocity |
| Acceleration | full stick from rest, accel 0.06 s | max speed (5.5) reached by t = 0.06 s |
| Aim memory | move right then neutral | aim stays right |
| Assist | cone 25°/8 u, candidate 15° at 5 u | snaps; off → unchanged; 30° → unchanged |
| Lock | lock held, walk up | aim frozen; release → next move updates |
| Lock disabled | toggle off, held | button ignored |
| Buffer 0.12 | dash pressed in recovery, recovery ends ≤0.12 s later | dash executes at recovery end, once |
| Buffer 0 | dash pressed in recovery | ignored |
| Perfect dodge | dash start within 0.08 s before landTime, overlapping | one `PerfectDodged` per (attackId, PlayerId) |
| Outside window | dash 0.09 s before land, hit lands in i-frames | avoided log, no PerfectDodged |
| Time scale | pause (0) + slow (0.3) | 0 wins; slow expires in unscaled time |

## Design Notes

Toggles: `SessionToggles` holds `bool?` overrides; effective = override ?? config flag, so Inspector edits still apply until the menu overrides. Time-scale requests expire on unscaled time so pause/slow never freeze their own expiry. Dash passes through enemies via `Rigidbody2D.excludeLayers` = Enemy during the dash; walls block. While `Time.timeScale == 0` the reader does not push presses into the buffer (menu Submit = Dash must not leak).

## Implementation Notes

- Implemented directly by the build agent (it was itself a delegated subagent; no nested implementation subagent). Checkpoints were pre-approved by the caller's task brief.
- Builder opens the scene before loading assets (opening a scene unloads assets loaded earlier, which nulled scene references).
- `InputSystemUIInputModule` fields set via SerializedObject; the `actionsAsset` setter throws in batchmode.
- Legacy uGUI `Text` (built-in LegacyRuntime font) instead of TextMeshPro, to avoid importing TMP Essentials for placeholder UI.
- `FindFirstObjectByType` is obsolete in 6000.6; tests use `FindAnyObjectByType`.
- Pause resume frame discards presses (PlayerInputReader.DiscardPressesThisFrame) because EventSystem may run before the reader.
